## Candidate Skill Rules
- Before building a new family, force a four-part scaffold: hypothesis, implementation, hint, settings.
- Translate each official hint into one narrow diagnostic branch, then stop.
- Keep first batch design to one semantic signal and one lever change.
- Use the course examples as onboarding templates, not as winners or account defaults.
- If a family shows a shallow ridge, keep the axis that is working fixed and sweep only the nearby lever.
- If a tighter probe fails to improve the ridge and the shown test-period or overall readout turns negative, stop polishing and branch to a distinct family instead of adding another cosmetic smoothing tweak.
- Do not let a positive TEST slice rescue a family when IS stays negative and no real Check Submission / non-null subuniverse evidence appears; kill or branch instead of polishing.
- When branching for lower correlation, prefer a genuinely new information source or a grouping / neutralization change before spending the lane on window-length tuning alone.
- Before calling a family robust, probe small parameter changes and check that it survives the relevant universe / region shifts instead of only the current backtest slice.
- Keep example-derived settings as starting points to verify, not as trusted defaults.
