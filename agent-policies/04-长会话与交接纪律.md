# 长会话与交接纪律

## 何时读取

遇到下列情况时读取本文件：

- 任务会跨多个上下文窗口或多个 AI 会话
- 需要显式进度、阻塞、证据或接力
- 需要用 cycle 管理正式研究工作

默认不读本文件。只有当聊天上下文已经不足以承载任务状态时才加载。

除链接以外，文中的路径约定默认按项目根目录解释。

## 进入 Harness 的触发条件

满足任一条件，就进入 harness 模式：

- 任务不会在当前会话内稳定收尾
- 任务需要中断后继续
- 需要明确记录 feature 状态
- 需要在完成前挂载证据
- 需要生成 handoff 文档给下一轮会话

入口：

1. [../harness/AGENTS.md](../harness/AGENTS.md)
2. `./harness/init.sh`
3. `./harness/coding-session.sh status`
4. `./harness/coding-session.sh doctor`
5. `./harness/coding-session.sh resume-brief`
6. `./harness/coding-session.sh session-open`
7. `./harness/coding-session.sh start`

不要只依赖聊天记忆保存进度。

## 长会话真相源

- 当前 cycle 入口：
  `../harness/active-cycle.txt`
- 当前任务状态：
  active cycle JSON
- 当前会话状态：
  `../harness/progress.md`
- 决策与路线变化：
  `../harness/decision-log.md`
- 证据：
  `../harness/artifacts/`
- 周期报告和接力文档：
  `../harness/reports/`
- 执行启动包：
  `../runs/session-briefs/`

## 更新纪律

### `progress.md`

当下列内容变化时更新：

- 当前 feature
- 当前阻塞
- 下一步
- 关键产物路径

### `decision-log.md`

当下列内容变化时更新：

- 研究方向切换
- 优先级切换
- 关键假设变化
- 重要取舍结论

### `artifacts/`

当完成依赖验证、测试证明、截图或结果留存时写入。

### `reports/`

用于持久化：

- `cycle-report`
- `resume-brief`

## 交接顺序

如果一个 cycle 进入收尾，按这个顺序：

1. `cycle-summary`
2. `cycle-report`
3. `resume-brief`
4. `session-open`
5. `cycle-close`
6. `cycle-archive`

`cycle-close` 不等于归档。

## 硬规则

- 每个会话只推进一个 active feature。
- 不要手工伪造完成状态。
- 还有 `pending` 或 `in_progress` 时，不关闭 cycle。
- 没有读当前 handoff 文档时，不直接接着做长任务。
- 需要证据的完成项，证据先落地，再标完成。
